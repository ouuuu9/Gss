# GSS 部署手册

> 适用：Spring Boot 3.2.5（Java 17）+ Vue 3（静态构建）+ MySQL 8
> 覆盖两个目标：**本机 Linux（WSL2）** 与 **云服务器**
> 两者 90% 相同，差异集中在「端口暴露」和「开机自启」，看第五、六节即可。

---

## 一、部署架构

```
                    ┌──────────────────────────────┐
   浏览器  ────────►│  Nginx :80                   │
                    │   /            → dist 静态文件 │
                    │   /api  ──►  127.0.0.1:8080  │
                    │   /ws   ──►  127.0.0.1:8080  │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │  Spring Boot (jar) :8080     │
                    │  systemd 托管，环境变量注入   │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │  MySQL 8 :3306  (库名 gss)   │
                    └──────────────────────────────┘
```

**要点**：前端构建产物是纯静态，`request.js` 的 `baseURL` 是 `'/'`，
所以生产环境**不需要改任何前端配置**——只要 Nginx 把 `/api` 和 `/ws` 反代到后端即可。

## 二、前置依赖

| 组件 | 版本 | 用途 | 安装（Debian/Ubuntu） |
|---|---|---|---|
| JDK | **17**（必须） | 跑后端 jar | `sudo apt install openjdk-17-jre-headless` |
| MySQL | 8.0 | 数据库 | `sudo apt install mysql-server` |
| Nginx | 任意稳定版 | 静态文件 + 反代 | `sudo apt install nginx` |
| Node.js | 18+（仅构建机需要） | 构建前端 | 不必装在生产机 |

> 生产机**不需要** Maven 和 Node——构建好的 jar 与 dist 直接传上去即可。

## 三、构建（在开发机做，Windows 也行）

```powershell
# 后端 → 可执行 jar（约 55 MB，含嵌套依赖）
cd C:\Document\Develop\Project\Gss\backend
mvn package -DskipTests
# 产物：target\gss-backend-1.0.0.jar

# 前端 → 静态文件
cd ..\frontend
npm run build
# 产物：dist\
```

> ⚠ `mvn package` **不要加 `-o`**：离线模式会因缺 `spring-boot-maven-plugin` 失败。

## 四、部署到本机 WSL2

### 4.1 安装依赖

```bash
sudo apt update
sudo apt install -y openjdk-17-jre-headless mysql-server nginx
```

### 4.2 建目录

```bash
sudo mkdir -p /opt/gss /var/www/gss
sudo chown -R $USER:$USER /opt/gss
```

### 4.3 传文件

在 **Windows 侧**（PowerShell）执行：

```powershell
# 假设 WSL 用户名是 yourname，用 WSL 的 IP 或 \\wsl$\ 路径都行
scp backend\target\gss-backend-1.0.0.jar yourname@localhost:/opt/gss/gss.jar
# 前端整个目录
scp -r frontend\dist\* yourname@localhost:/var/www/gss/
```

> 更省事的方式：直接在 WSL 里 `cd /mnt/c/Document/Develop/Project/Gss` 访问 Windows 文件，
> 用 `cp` 拷过去即可（WSL 默认挂载了 C 盘）。

### 4.4 WSL2 的端口问题（关键）

WSL2 有自己的虚拟网卡，Windows 访问 WSL 服务**通常**能用 `localhost`，
但如果访问不到，用 WSL 的 IP：

```bash
# 在 WSL 里查
hostname -I | awk '{print $1}'
```

然后在 Windows 浏览器访问 `http://<那个IP>/`。

> 想长期用 `localhost`，需要在 Windows 侧加端口转发（管理员 PowerShell）：
> ```powershell
> netsh interface portproxy add v4tov4 listenport=80 listenaddress=0.0.0.0 connectport=80 connectaddress=<WSL_IP>
> ```
> 但 WSL 的 IP 每次重启会变，建议改用 `.wslconfig` 固定网络模式，或直接用服务器。

### 4.5 systemd 自启（WSL 需要先开启 systemd）

WSL 默认不带 systemd，编辑 `/etc/wsl.conf`：

```ini
[boot]
systemd=true
```

然后 PowerShell 里 `wsl --shutdown` 再重进。

## 五、部署到云服务器

### 5.1 与 WSL 的差异只有四处

| 项 | WSL2 | 云服务器 |
|---|---|---|
| 端口暴露 | Windows 本机 | **安全组 / 防火墙要开 80（可选 443）** |
| 访问方式 | localhost 或 WSL IP | 公网 IP 或域名 |
| 开机自启 | 需开 systemd | 默认就有 |
| 文件传输 | `scp` 或挂载 C 盘 | **必须 `scp`/`sftp`** |

### 5.2 上传

```bash
# 在本地开发机执行
scp backend/target/gss-backend-1.0.0.jar root@<服务器IP>:/opt/gss/gss.jar
scp -r frontend/dist/* root@<服务器IP>:/var/www/gss/
```

### 5.3 防火墙

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp   # 要用 HTTPS 时
sudo ufw status
```

**云厂商控制台的安全组也要开对应入站规则**——这一步最容易漏，表现为「服务器里 nginx 正常但外网访问不了」。

## 六、数据库

### 6.1 初始化（全新环境）

```bash
sudo mysql < /opt/gss/sql/gss.sql
```

> `gss.sql` 开头是 `DROP DATABASE IF EXISTS gss` —— **执行前确认这是新库**，会清空同名库。

### 6.2 老库升级（已跑过旧版）

按顺序执行迁移脚本：

```bash
sudo mysql gss < sql/20261105_refund_migration.sql        # 退款模块
sudo mysql gss < sql/20261114_eir_approval_migration.sql  # M1 办单审核
sudo mysql gss < sql/20261115_m2_voucher_migration.sql    # M2 凭证与核验
sudo mysql gss < sql/20261115_m3_lane_migration.sql       # M3 车道与配额
```

三个脚本都是**幂等**的（逐列/逐索引查 `information_schema` 再改），可重复执行；末尾有回滚段（需手动解开注释）。

### 6.3 建专用数据库账号（强烈建议）

不要用 root 跑应用：

```sql
CREATE USER 'gss'@'localhost' IDENTIFIED BY '换成强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON gss.* TO 'gss'@'localhost';
FLUSH PRIVILEGES;
```

## 七、后端起服务（systemd）

创建 `/etc/systemd/system/gss.service`：

```ini
[Unit]
Description=GSS Backend
After=network.target mysql.service

[Service]
Type=simple
User=gss
WorkingDirectory=/opt/gss
Environment=DB_USERNAME=gss
Environment=DB_PASSWORD=换成强密码
Environment=JWT_SECRET=换成至少32字节的随机串
Environment=TZ=Asia/Shanghai
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/gss/gss.jar
Restart=on-failure
RestartSec=5
StandardOutput=append:/var/log/gss/backend.log
StandardError=append:/var/log/gss/backend.err.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo mkdir -p /var/log/gss && sudo chown gss:gss /var/log/gss
sudo useradd -r -s /usr/sbin/nologin gss   # 没这个用户才建
sudo systemctl daemon-reload
sudo systemctl enable --now gss
sudo systemctl status gss
```

### 三个必须改的环境变量

| 变量 | 说明 |
|---|---|
| `DB_PASSWORD` | 别用默认 123456 |
| `JWT_SECRET` | **必须改**。默认值是开发用的，泄露等于任何人都能伪造登录态；至少 32 字节 |
| `DB_USERNAME` | 用上一步建的 `gss` 账号，不要 root |

## 八、Nginx 配置

`/etc/nginx/sites-available/gss`：

```nginx
server {
    listen 80;
    server_name _;          # 有域名就填域名

    root /var/www/gss;
    index index.html;

    # 前端路由（history 模式）必须回落到 index.html，否则刷新子页面 404
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 大屏 WebSocket
    location /ws {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|svg|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/gss /etc/nginx/sites-enabled/
sudo nginx -t          # 语法检查，必须先过
sudo systemctl reload nginx
```

> **两个最容易漏的点**：① `try_files ... /index.html`（Vue history 模式刷新 404）
> ② `/ws` 的 `Upgrade`/`Connection` 头（少了 WebSocket 连不上，大屏不更新）

## 九、验证清单

按顺序过，哪一步失败就停在哪：

| # | 检查 | 命令 / 预期 |
|---|---|---|
| 1 | 后端进程 | `systemctl status gss` → active (running) |
| 2 | 后端直连 | `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8080/api/auth/login -X POST -H "Content-Type: application/json" -d '{"username":"admin","password":"123456"}'` → **200**（405/500 说明后端没起） |
| 3 | 数据库连通 | 后端日志里不应有 `Communications link failure` |
| 4 | Nginx 静态 | 浏览器打开 `http://<IP>/` → 登录页 |
| 5 | Nginx 反代 | 登录页输入 `admin/123456` → 能进首页 |
| 6 | 前端路由刷新 | 进首页后按 F5 → 不应 404 |
| 7 | 大屏 WebSocket | 打开「数据大屏」→ 数据应自动刷新（不刷新就是 `/ws` 没配对） |
| 8 | 登录态 | 关浏览器重开 → 仍是登录状态（JWT 存 localStorage） |

## 十、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `Port 8080 was already in use` | 旧实例没退 | `sudo lsof -i:8080` 找到 PID 杀掉 |
| 登录返回 500 | 数据库连不上 / 表不存在 | 看 `/var/log/gss/backend.err.log`，确认 `gss.sql` 跑过 |
| 前端能打开但登录 404 | Nginx 没配 `/api` 反代 | 检查 `location /api/` 段 |
| 刷新子页面 404 | 缺 `try_files` | 补 `/index.html` 回落 |
| 大屏不动 | `/ws` 缺 Upgrade 头 | 按第八节补 |
| 外网访问不了但服务器内正常 | **云安全组没开 80** | 控制台加入站规则 |
| 中文乱码 | 数据库字符集 | 确认建库时 `utf8mb4`，JDBC URL 带 `characterEncoding=utf8` |
| 时间差 8 小时 | 容器/服务器时区 | systemd 里 `Environment=TZ=Asia/Shanghai`，JDBC URL 带 `serverTimezone=Asia/Shanghai` |

## 十一、可选：HTTPS 与域名

有域名时，用 certbot 一条命令：

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your.domain.com
```

certbot 会自动改 Nginx 配置并加续期定时任务。**没有域名就别折腾 HTTPS**，自签证书浏览器会拦，答辩演示反而添麻烦。

## 十二、答辩演示的最小路径

如果只是要给老师演示，**不必上服务器**：

1. 开发机 `mvn package` + `npm run build`
2. 本机起 MySQL（3307 实例即可）
3. `java -jar gss-backend-1.0.0.jar` + 用任意静态服务器托管 dist（或用 `npm run preview`）
4. 浏览器打开演示

服务器部署的意义是「随时可访问」，答辩场景用本机更稳——**网络和服务器故障是最常见的演示事故**。
