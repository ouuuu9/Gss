# 可读性重构变更摘要

> 日期：2026-10-31  
> 代码基准：当前工作区未提交改动（`backend/`、`frontend/src/`）  
> 文档性质：变更记录，非接口文档；重构前后对外行为保持一致

---

## 1. 概述

### 1.1 背景与目标

系统功能与接口已经稳定，但代码中存在较多"写得短"而非"读得顺"的写法：只做一行转发的私有方法、`stream/filter/reduce` 链式调用、嵌套三元表达式、`var`、分散的字符串字面量、前端表单校验的 `validate(callback)` 回调等。这些写法本身没有错误，但增加了阅读时的跳转与脑内展开成本。

本轮重构的目标只有一个：**在不改变任何功能、接口签名、异常语义与并发行为的前提下，降低阅读成本**。不新增依赖，不调整分层，不追求代码行数减少。

### 1.2 风格原则摘要

| 原则 | 落地方式 |
|---|---|
| 可读性优先 | 判断与分支写成一眼能读懂的形式，不为压缩行数牺牲直观性 |
| 减少封装与包装 | 删除只做一行转发的私有方法/函数，调用方直接使用被封装目标 |
| 提前返回拍平嵌套 | 用 `if (...) { return; }` / `continue` 替代多层缩进与链式 lambda |
| 优先显式 `if/for/try` | 用普通循环替代 `stream + filter/map/reduce`，用 `if` 替代嵌套三元 |
| 命名直观 | 变量名表达业务含义（如 `dispatchEirIds`、`existingExpireAt`、`driverOptions`） |
| 显式类型 | 后端 `var` 改为显式类型，便于确认实际类型 |
| 中文注释 | 注释解释"为什么"，而非复述代码 |
| 保持语义 | 查询/校验结果、异常文案、HTTP 状态码、前端提示文案均不变 |
| 不新增依赖 | 后端与前端依赖清单未改动 |

## 3. 代表性改动

### 3.1 后端

**（1）删除只做一行转发的私有方法**

`AppointmentService` 的 `casEirStatus`、`GateService` 的 `findEirByTractorAndStatus` 都只是转发给下游组件，删掉后调用点直接调用目标：

```java
// 改前（AppointmentService）
casEirStatus(update, eir.getStatus());

// 改后
EirStatus.casStatus(eirMapper, update, eir.getStatus());
```

```java
// 改前（GateService）
EirOrder eir = findEirByTractorAndStatus(tractor.getId(), Constants.ST_APPOINTED);

// 改后
EirOrder eir = eirMapper.selectEarliestByTractorAndStatus(tractor.getId(), Constants.ST_APPOINTED);
```

理由：读者不需要再跳进一层确认"这个方法到底做了什么"，调用链少一跳。

**（2）`stream / reduce` 改普通 `for`**

`DashboardService` 的报表金额汇总、`DriverService` 的司机过滤、`FeeService` 的待缴费 ID 收集均改为显式循环，过滤条件用 `continue` 拍平：

```java
// 改前（FeeService）
List<Long> payableIds = fees.stream()
        .filter(f -> f.getCompanyId().equals(operator.getCompanyId()))
        .filter(f -> f.getPayStatus() == null || f.getPayStatus() == 0)
        .map(FeeRecord::getId)
        .toList();

// 改后
List<Long> payableIds = new ArrayList<>();
for (FeeRecord fee : fees) {
    if (!fee.getCompanyId().equals(operator.getCompanyId())) {
        continue;
    }
    if (fee.getPayStatus() != null && fee.getPayStatus() != 0) {
        continue;
    }
    payableIds.add(fee.getId());
}
```

理由：循环体逐行可读，断点与日志定位更直接，不依赖读者熟悉链式算子语义。

**（3）嵌套三元改 `if` + 提前返回**

`AuthService.toLoginUser`、`JwtUtil` 的 claims 解析、`AuditLogAspect` 的文本截断、`TractorService` 的轴数默认值均改为显式分支：

```java
// 改后（AuthService）
Long companyId = user.getCompanyId();
if (Constants.ROLE_ADMIN.equals(user.getRole()) || Constants.ROLE_GATE.equals(user.getRole())) {
    companyId = null;
}
return LoginUser.builder()
        ...
        .companyId(companyId)
        .build();
```

理由：码头端角色不归属运输公司的规则单独成段，注释能贴着规则写，不需要在 builder 链中读懂三目运算。

**（4）业务字面量改为 `Constants`**

`SysUserService` 中的 `"ADMIN"` / `"GATE"` / `"DRIVER"`、`DashboardService` 中的 `"GATE_IN"` / `"GATE_OUT"` 改为 `Constants.ROLE_*`、`Constants.ST_*`：

```java
boolean dockRole = Constants.ROLE_ADMIN.equals(role) || Constants.ROLE_GATE.equals(role);
```

理由：拼写错误在引用处就能被统一发现，角色/状态取值只有一个来源。

**（5）`var` 改显式类型**

`AppointmentController`、`EirController` 中的 `var scope` 改为 `CompanyScope.Scope scope`，方法返回值类型在调用处即可确认。

**（6）其余小改动**

- `EirService.getById` 的两段角色校验由 `else if` 嵌套改为两个独立 `if`，公司校验不通过时直接抛出；
- `EirService.update` 的 `Arrays.asList(...).contains(...)` 改为 `boolean editable = A || B`；
- `EirController` 导出使用的大对象字面量 lambda 展开为语句块，箱型描述先构造 `containerDesc` 再返回；
- `GlobalExceptionHandler` 的 `NoResourceFoundException` 由全限定名改为 `import`；
- `ScreenWebSocketHandler` 的 `removeIf` 改为 `for` + `sessions.remove(session.getId())`（`sessions` 为 `ConcurrentHashMap`，遍历中删除安全）。

### 3.2 前端

**（1）抽取 `redirectToLogin`，拍平 Blob 错误分支**

`api/request.js` 中 401/403 的"提示 + 清本地凭证 + 回登录页"原本在响应拦截器和 Blob 错误分支复制了三份，现收敛为一个函数；Blob 错误解析改为 `JSON.parse(await error.response.data.text())` 后直接判断。

理由：登录失效的处理只有一处，改文案或改存储键不需要多点同步。

**（2）提前返回替代嵌套判断**

`utils/download.js` 的 `getFilenameFromResponse` 改为：

```js
const disposition = response.headers['content-disposition']
if (!disposition) {
  return fallback
}
const match = disposition.match(/filename\*=UTF-8''(.+)/)
if (!match) {
  return fallback
}
return decodeURIComponent(match[1])
```

**（3）表单校验由 `validate(callback)` 改为 `await` + 提前返回**

`Login.vue`、`Eir.vue`、`ApptBookDialog.vue` 及 `useCrudPage.js` 的提交逻辑统一为：

```js
const valid = await formRef.value.validate().catch(() => false)
if (!valid) {
  return
}
```

理由：提交主流程回到函数第一层，不再被回调包住；`catch(() => false)` 保留"校验失败即中止"的原语义。

**（4）`firstAccessiblePath` 单一来源**

该函数原本在 `Login.vue` 内有一份本地副本，`Layout.vue` 又写了一份等价的 `homePath` 计算。现由 `router/index.js` 导出，登录页与主布局统一复用。

理由：菜单权限规则只维护一处，新增角色或调整菜单顺序时不会出现三个入口不一致。

**（5）删除纯转发的 `doCheckin` / `doCheckout`**

`Gate.vue` 两个函数仅分别调用 `handle('checkin')` / `handle('checkout')`，删除后模板直接绑定 `handleGateOp('checkin')` / `handleGateOp('checkout')`，函数本身也改名为更直观的 `handleGateOp`。

**（6）其余重命名与去重**

- `Eir.vue`：`dispatchTargets` → `dispatchEirIds`（实际存的是 ID 列表，而非目标对象），并移除未使用的 `useRouter`；
- `Report.vue`：四处 `reduce` 改为一次累加循环；合计行的状态判断改为 `COUNT_FIELDS` / `AMOUNT_FIELDS` 常量 + `sumField(prop)`；
- `Dashboard.vue`、`Screen.vue`：删除页面内手写的状态/业务类型标签映射，改用 `utils/dict.js` 的 `EIR_STATUS`、`BUSINESS_TYPE`；
- `UserManage.vue`：模板内联的司机过滤表达式抽为 `driverOptions` 计算属性；
- `AuditLog.vue`：`resetQuery(() => dateRange = null)` 改为具名函数 `resetDateRange`；
- `Layout.vue`：`openeds` 重命名为 `defaultOpenedGroups`。
